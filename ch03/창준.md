# Chapter 03 - 창준

## 핵심 내용

- 툴팁 하나를 두고 "여닫기 → 하나만 열기 → 바깥 클릭 닫기 → 화면 이탈 방지"로 요구사항이 쌓인다. 각 단계마다 **상태를 누가 소유하는가**와 **위치를 누가 계산하는가**가 달라진다.
- 하나만 열리게 하는 방법은 셋이다. Context로 열린 id 하나만 보관(#2-1), 전역 클릭 감지로 이전 것을 닫기(#2-2), `<details name>`으로 브라우저에 위임(#2-3). 뒤로 갈수록 우리가 쓰는 코드가 줄어든다.
- **click-outside 패턴에서 `ref`는 여닫는 트리거까지 감싸야 한다.** `#2-2`는 `ref`를 툴팁 레이어에만 붙였는데, 레이어는 트리거의 자식이라 `layer.contains(트리거) === false` — 즉 트리거 클릭이 "바깥 클릭"으로 오인된다. 캡처 단계의 `handleClose(toggle(false))`가 먼저 실행되고 버블 단계의 `handleClick(toggle(prev => !prev))`이 그 `false`를 다시 뒤집어, **트리거를 눌러도 안 닫히는** 버그가 된다. `ref`를 트리거로 올린 것이 `#2-2-1`.
- 캡처가 버블보다 먼저라는 점이 핵심이다. `document`는 전파 경로의 최상단이라 `addEventListener(..., true)`로 등록한 리스너는 React의 `onClick`(버블)보다 항상 먼저 실행된다. 그래서 `handleClick`에서 `stopPropagation()`을 불러도 이미 늦다.
- `<details name>`(#2-3)은 같은 그룹에서 하나만 열리게 해주지만 **바깥 클릭으로 닫아주지는 않는다.** light dismiss는 `popover="auto"`의 기능이고 `details`에는 없다. 배타성만 얻고 닫기는 여전히 직접 처리해야 한다.
- 화면 이탈 방지(#3)는 `rootRect.bottom + targetRect.height < vh` 한 줄로 방향을 정하는 문제다. `useLayoutEffect`로 페인트 직전에 계산해 잘못된 위치가 한 프레임도 보이지 않게 한다.
- CSS Anchor Positioning(#4)은 이 계산을 통째로 브라우저에 넘긴다. 다만 `position-try`의 넘침 판정은 **컨테이닝 블록**을 기준으로 하므로 `position: absolute`면 ICB(문서 좌상단에 고정된 뷰포트 크기 사각형)가 기준이 되어, 페이지 아래쪽 요소는 어떻게 뒤집어도 이미 밖이라 뒤집기가 걸리지 않는다. → 상세는 아래 심화 섹션

## 심화 1: 왜 트리거를 눌러도 안 닫혔나

`#2-2`의 DOM 구조는 이렇다.

```
document                     ← useClickOutside 리스너 (캡처)
└─ span.tooltip-root
   └─ span.tooltip-trigger   ← onClick={handleClick} (버블)
      └─ span.tooltip-layer  ← ref
```

### 1층. `contains()`의 방향

`A.contains(B)`는 **"B가 A 안에 있는가"** 로, A 기준 아래쪽(자손)만 본다.

```js
trigger.contains(layer); // true   큰 상자 안에 작은 상자가 있다
layer.contains(trigger); // false  작은 상자 안에 큰 상자는 없다
node.contains(node); // true   자기 자신도 포함
```

`ref`가 레이어에 붙어 있으니 기준이 레이어가 된다. 트리거는 레이어의 **부모**라 "바깥"으로 판정된다.

### 2층. 캡처가 버블보다 먼저

클릭은 **캡처(위→아래) → 타깃 → 버블(아래→위)** 순으로 흐른다. `document`는 최상단이라 캡처에서 가장 먼저 지나가고, React의 `onClick`은 루트 컨테이너에서 버블 단계에 처리된다.

```
캡처  document ─▶ root ─▶ trigger
        └ useClickOutside → toggle(false)          ①
버블  trigger ─▶ root ─▶ document
        └ handleClick     → toggle(prev => !prev)  ②
```

### 3층. `prev`는 현재 상태가 아니다

`prev`는 `isOpen`이 아니라 **업데이트 큐에 쌓인 마지막 값**이다.

```
시작값        true
① toggle(false)          → 대기값 false
② toggle(prev => !prev)  → prev는 ①의 결과인 false → !false = true
최종          true   (열린 채 유지)
```

닫기 함수는 **호출된다.** 다만 그 결과를 `handleClick`이 곧바로 되돌린다. 닫힌 상태에서는 `TooltipDescription`이 마운트되지 않아 리스너 자체가 없으므로, **여는 건 되고 닫는 것만 안 되는** 증상이 나온다.

### 해결

`ref`를 트리거로 올려 트리거와 레이어를 모두 울타리 안에 넣는다. 그러면 `contains()`가 `true`가 되어 캡처 콜백이 아예 실행되지 않고, `handleClick` 하나만 남는다.

| | 트리거가 ref 안? | 실행되는 것 | 결과 |
| --- | --- | --- | --- |
| #2-2 | ❌ 밖 | `handleClose` + `handleClick` | 안 닫힘 |
| #2-2-1 | ⭕ 안 | `handleClick`만 | 닫힘 |

`stopPropagation()`은 해결책이 아니다. 캡처는 이벤트가 트리거에 닿기 전에 이미 지나갔고, `handleClick` 자신이 실행되는 것도 막을 수 없다.

## 심화 2: anchor positioning이 뒤집히지 않은 이유

`#4`는 `position-try`로 뒤집기를 선언했는데 화면 아래쪽 툴팁이 뒤집히지 않는다.

### 컨테이닝 블록이 판정 기준이다

`position: absolute`는 **가장 가까운 positioned 조상**을 기준으로 삼고, 없으면 **ICB**로 떨어진다. ICB는 크기는 뷰포트와 같지만 **문서 좌상단에 고정**된 사각형이다.

`.anchor-target`은 `.details`의 형제이고 위로 올라가도 positioned 조상이 없어 ICB가 컨테이닝 블록이 된다.

```
문서
┌──────────────┐ y=0
│   ICB        │  높이 = 뷰포트 높이
└──────────────┘
      ⋮
   툴팁 4        ← 이미 ICB 밖
```

### 후보가 전부 탈락하면 원래 위치를 쓴다

```
원래 위치   → ICB 밖 → 넘침
flip-block  → ICB 밖 → 넘침
flip-inline → ICB 밖 → 넘침
→ 통과 후보 없음 → 원래 위치 사용 (뒤집기 없음)
```

### `position: fixed`로 바꾸면 해결된다

`fixed`는 컨테이닝 블록이 **뷰포트**라 판정이 실제 화면 기준이 된다.

```
원래 위치   → 화면 아래 넘침 → 탈락
flip-block  → 들어맞음 → 채택 ✅
```

앵커 포지셔닝이 `popover`·top layer와 함께 소개되는 것도 그쪽 요소들이 기본적으로 뷰포트를 컨테이닝 블록으로 갖기 때문이다. `anchor()`가 위치를 직접 계산해 주므로 `absolute`의 "부모를 따라다니는" 성질은 애초에 필요 없다.

### 사용법 요약

```scss
.anchor[open] {
  anchor-name: --tooltip-anchor; // ① 닻에 이름
}
.anchor[open] + .anchor-target {
  position: fixed; // ② 컨테이닝 블록 = 뷰포트
  position-anchor: --tooltip-anchor; // ③ 닻 지목
  position-area: bottom right; // ④ 3×3 격자에서 칸 선택
  position-try-fallbacks: flip-block, flip-inline;
  position-visibility: anchors-visible; // 닻이 안 보이면 함께 숨김
}
```

`anchor-name`을 `[open]`일 때만 부여하면, 여러 항목이 같은 이름을 써도 `name="tooltip"` 덕분에 열린 게 하나뿐이라 닻도 하나만 존재한다.

지원 범위는 Chrome·Edge 125+, Safari 26+, Firefox 147+. `@supports`로 감쌀 때 `anchor-name`이 아니라 `position-try-fallbacks`로 검사해야 한다. `anchor()`는 되지만 뒤집기는 안 되는 중간 버전(Safari 18.2~18.3)을 걸러내기 위해서다.

## 메모

- `#3`은 `ViewportContextProvider`를 감싸야 동작한다. Provider가 없으면 `useContext`가 기본값(`width: 0, height: 0`)만 돌려주어 `rootRect.bottom + height < 0`이 항상 거짓이 되고, 모든 툴팁이 무조건 위로 펼쳐진다. `Example.tsx`에서 `#3`만 Provider로 감쌌다.
- `#3`의 `useLayoutEffect` 의존성이 `[rootRef, targetRef, vt, vl, vw, vh]`라 **툴팁을 여는 시점에는 재계산되지 않는다.** 닫힌 `<details>`의 자식은 렌더링되지 않아 `getBoundingClientRect()`가 0을 돌려주므로, 열 때 한 번 다시 재야 정확하다. `needUpdate` 인자를 만들어 뒀지만 아직 연결하지 않았고 의존성 배열에도 없다. 원본 저장소의 바닐라 버전은 `toggle` 이벤트에서 `notifyScrollInfoChanged()`를 직접 호출해 이 문제를 해결하고 있다.
