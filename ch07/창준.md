# Chapter 07 - 창준

## 핵심 내용

- 이미지에 처음부터 `src`를 넣지 않고 뷰포트 진입 시점에 요청을 시작하는 지연 로딩
- `getBoundingClientRect()`를 이용한 직접 교차 계산
- `IntersectionObserverEntry`와 `isIntersecting`을 이용한 관찰
- 네이티브 `<img loading="lazy">`와 직접 `src` 삽입 방식의 차이
- Vanilla JavaScript와 React 구현 비교
- 저해상도 배경과 원본 이미지 전환을 이용한 placeholder

## 예제 코드

- `src/examples/ch07/changjun/1_r.tsx`: React에서 이미지와 뷰포트 좌표를 직접 비교
- `src/examples/ch07/changjun/2_r.tsx`: 네이티브 lazy loading과 IntersectionObserver fallback
- `src/examples/ch07/changjun/3_v.tsx`: Vanilla JavaScript 지연 로딩
- `src/examples/ch07/changjun/4_r.tsx`: 저해상도 배경 placeholder
- `src/examples/ch07/changjun/lib/`: React·Vanilla IntersectionObserver 유틸

## 실행 방법

```bash
npm install
npm run dev
```

홈에서 `Chapter 07`과 `창준`을 선택한다.

## 메모

- `data-src`는 주소 문자열만 보관하므로 브라우저가 이미지 요청을 시작하지 않는다.
- 실제 `src`가 들어가는 순간 네트워크 요청과 디코딩이 시작된다.
- 한 번 불러온 이미지는 Observer 관찰을 해제해 중복 작업을 막는다.
- 네이티브 `loading="lazy"`는 브라우저 힌트이므로 정확한 요청 시점을 보장하지 않는다.
