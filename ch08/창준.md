# Chapter 08 - 창준

## 핵심 내용

- `currentPage`, `setPage`를 이용한 전통적인 페이지네이션
- 임의 응답 시간으로 서버 요청을 흉내 낸 mock fetcher
- 일반 상태 업데이트와 React 19 `useTransition`의 렌더링 우선순위 비교
- 다음 페이지 존재 여부를 한 항목 더 요청해서 확인하는 무한 스크롤
- IntersectionObserver sentinel을 이용한 다음 페이지 요청
- 페이지 단위 `content-visibility: auto` 렌더링 최적화
- `content-visibility`와 Windowing의 차이

## 예제 코드

- `src/examples/ch08/changjun/1_tranditional/`: 페이지 요청과 전통 페이지네이션
- `src/examples/ch08/changjun/2_transition/`: 1,500개 항목으로 일반 업데이트와 Transition 비교
- `src/examples/ch08/changjun/3_infiniteScroll/`: 무한 스크롤 Fetcher와 `content-visibility`

## 실행 방법

```bash
npm install
npm run dev
```

홈에서 `Chapter 08`과 `창준`을 선택한다.

## 메모

- `waitFor`는 네트워크 대기를 흉내 낼 뿐 메인 스레드를 막지 않는다.
- Transition은 별도 스레드가 아니라 React 렌더링을 중단 가능한 낮은 우선순위 작업으로 표시한다.
- `content-visibility`는 DOM을 제거하지 않고 화면 밖 페이지의 Layout과 Paint를 생략한다.
- DOM 수와 React 렌더링, 메모리가 병목이면 TanStack Virtual 같은 Windowing이 필요하다.
